Architecture

One Rust workspace, one Android shell. All the interesting logic — the FSRS scheduler, the alphabet gate, question generation, dictionary search, the sync merge layer — lives in Rust and is unit-tested there; Kotlin is UI and glue.

Workspace layout

crates/
├── core             greek-core — the brain, on-device SQLite
│   ├── srs/         FSRS scheduling, review log, daily new-card cap (10/day),
│   │                interval previews, sub-day learning steps
│   ├── curriculum/  chapter gating (80% of prev at 30d stability),
│   │                the alphabet gate (24-q check ≥22, organic lane)
│   ├── questions/   measured assessment: MCQ + accent-tolerant typed answers
│   ├── morphology/  Morpheus DB access, accent-stripping normalizer
│   ├── search/      FTS5 + BM25 dictionary search w/ exact-match boost
│   ├── reader/      tokenization + tap-to-parse
│   ├── sync/        CRDT merge: HLC, G-set apply, FSRS fold-replay, LWW settings
│   └── db/          schema + migrations (user_version → 3)
├── uniffi-bindings/ UniFFI surface; cdylib consumed by Kotlin via JNA
├── sync-nostr/      NIP-44 self-encrypted nostr spool transport
└── cli/             TODO stub
android/             Jetpack Compose app (6 screens over UniFFI)
spikes/iroh/         validated iroh-docs Android spike (aarch64 + x86_64)
tools/data-pipeline/ morphology DB builder + gloss-override applier
data/                cards (5 decks, 1,183 total), curated gloss overrides

Technology picks

ChoiceWhy
fsrs 2.x (Rust)The real FSRS algorithm — full per-rating next_states, 90% desired retention — not an SM-2 tweak.
UniFFIKotlin bindings generated from Rust, so pedagogy bugs get fixed once, in Rust, for all future front-ends (Tauri desktop is next).
SQLite (rusqlite) + FTS5State + morphology in plain files, WAL mode, queryable, exportable, owned by the user.
iroh 1.x / iroh-docsDirect device-to-device sync; share-ticket QR pairing with the write capability in the ticket.
nostr-sdk 0.43 (NIP-44)Store-and-forward sync through relays as untrusted storage; ciphertext-only events, chunked at 48 KiB.
Hybrid Logical ClockTotal order over a merged review history even under device clock skew, so FSRS replay is deterministic everywhere.
Jetpack Compose + Material 3Native Android shell; system-follow dark theme; nothing exotic.

Tests

  • 81 unit tests in greek-core (SRS scheduling, gates, questions, sync replay, migrations).
  • +6 each in the UniFFI integration tests and sync-nostr unit tests; workspace total 93 #[test] items.
  • A live-relay round-trip test (#[ignore] by default) verifies the nostr transport against public relays.
  • Run everything: cargo test --workspace.

Contributing

Issues and PRs at github.com/EthnTuttle/greek. The codebase is organized so that pedagogic changes happen in crates/core against the tests; new curator-editable gloss fixes go in data/overrides/lemma_glosses.tsv (one TSV row, no code) and are applied by tools/data-pipeline/overrides/apply_overrides.py. High-leverage areas per the plan: LSJ ingestion, reader corpus growth with coverage-aware difficulty, the Tauri desktop shell, and the sync UI wiring.
